# ADR-001: Wi-Fi/TCP Transport Only, No Bluetooth

**Status:** Accepted

## Context

The user owns an ACEBOTT QD001 smart car (ESP32-based) and wanted to build a custom Electron desktop app to control it. Initially, the user preferred Bluetooth/BLE because it would allow the Mac to retain internet access while connected to the car (a significant user-experience advantage).

However, during the grill interview, the actual ACEBOTT firmware source code in this repository's `docs/` folder was inspected. No Bluetooth or BLE implementation was found in any of the firmware examples for the QD001 or QD005 kits — all example firmware uses Wi-Fi and TCP exclusively.

An alternative that could preserve internet access would be to reflash the car's firmware into Wi-Fi station mode (STA mode), allowing it to join the user's home network instead of hosting its own hotspot. This would require the user to perform a one-time firmware reflash and re-run the setup process on the car, but would use the same TCP protocol already proven to work.

## Decision

The Electron app will use Wi-Fi/TCP transport only. The car will remain in its current Wi-Fi Access Point (AP) mode, broadcasting the `ESP32-Car` hotspot exactly as it does today. No Bluetooth support will be built, and no firmware changes will be made to the car.

The trade-off is that the Mac will lose internet connectivity while connected to the app (unless it has a secondary connection such as Ethernet).

## Consequences

- **Simplicity:** Zero firmware changes, zero new protocol implementations. The car works exactly as it does with the official ACEBOTT phone app.
- **Consistency:** The custom Electron app follows the same network path as the existing phone app, reducing risk of unforeseen compatibility issues.
- **Development speed:** No time spent writing or debugging a BLE/GATT firmware layer on the ESP32.
- **User experience trade-off:** The user must choose between controlling the car or accessing internet; there is no simultaneous connectivity unless the Mac has Ethernet or another secondary connection.
- **Future extension:** If the user later wants internet access while using the app, the decision can be revisited as a separate plan that includes firmware reflash and STA-mode setup as part of its scope.
