# 02 — [security] Review and document the `sandbox: false` deviation from ADR-002

**What to build:** `main.ts`'s `BrowserWindow` sets `sandbox: false` in `webPreferences`, which weakens the isolation guarantee ADR-002 claims ("Maintains Electron's process-isolation sandboxing. If the renderer is compromised, it cannot directly access system resources."). This was introduced to work around Electron's default sandboxed preload environment rejecting a local `require()` inside `preload.ts`. This deviation was never surfaced in spec.md and needs to be either (a) eliminated by rewriting the preload script to avoid needing `sandbox: false` (e.g. bundling its dependencies inline instead of using `require()` on a local module, or converting the small amount of local preload code it depends on to be self-contained within `preload.ts` itself), or (b) explicitly documented and justified in spec.md/ADR-002 as an accepted, deliberate trade-off if no clean alternative exists.

Prefer (a) if practical — the fix should be small, since the preload script only needs to expose three functions via `contextBridge`, and the module it's importing was a small internal file.

**Blocked by:** None — can start immediately (can run in parallel with ticket 01, no shared files expected, but confirm no overlap with `main.ts`/`preload.ts` changes from ticket 01 before starting)

**Status:** ready
