# ADR-001: USB serial access moves from informational-only to actively opened, superseding ADR-002

## Context
`.gh-workflows/plans/20260815_083408-water-gun-control/grill/ADR-002.md` established that the app's USB handling must be non-invasive — a read-only filesystem presence check only, explicitly never opening or reading the serial device, macOS-only.

## Decision
This plan supersedes that constraint. The app will now use the `serialport` npm package to:
1. Enumerate ports cross-platform (Windows + macOS) via `SerialPort.list()` for the presence badge — still non-invasive, enumeration only.
2. Actually open the matched CH340 port (VID `0x1A86`/PID `0x7523`) at 115200 baud to stream real log data, gated behind an explicit user-initiated "Connect" action (see decisions.md #4) specifically to manage the port-contention risk that ADR-002's original non-invasive stance was never designed to address.

## Consequences
- A new runtime dependency (`serialport`) and its native-rebuild-for-Electron build step are introduced (see decisions.md #7).
- The existing presence badge (`isUsbSerialDevicePresent`/`startUsbStatusPolling` in `app/src/usbStatus.ts`) is rewritten to use `serialport`'s cross-platform enumeration instead of the macOS-only `/dev` directory scan, fixing the "USB: Not connected" bug on Windows as a side effect.
- Future work touching USB in this app should treat "opened for active streaming" and "detected via passive enumeration" as two distinct states, per decisions.md #4 — don't collapse them back into one.
